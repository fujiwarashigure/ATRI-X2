# ADR 0002：单文件 ≤ 600 行（目标，不是硬约束；用预算棘轮守）

- 状态：接受
- 上下文：`AGENTS.md` 一直写着"单文件目标 ≤ 600 行"，但**从来没有门禁**。

## 决定

1. **目标 600 行**，按**职责**拆，不按行数切（一个文件 = 一个关注点）。
2. 允许**暂时**超线：超过 600 行的文件必须进 `scripts/line_budget_baseline.json`，
   且**只能变短、不能变长**；新增文件不得超线（`python scripts/check_docs.py` 第 5 条断言）。
3. 拆分优先级看"是否枢纽 / fan-in / 是否频繁改动"，而不是看谁最长。

## 为什么用棘轮而不是硬卡

规则写死在散文里没有牙：本版之前实测 **80 个文件超过 600 行**（16 个 ≥800，最大
`atri_x/config/app_sections.py` 1225 行）。硬卡会逼出"为了过检查而乱拆"的坏重构；
棘轮则保证**方向正确且不倒退**，同时允许存量逐步消化。

## 现状（`python scripts/check_complexity.py --list`）

| 指标 | 当前 | 目标 |
| --- | --- | --- |
| 超 600 行文件 | 80 | ≤ 10 |
| 最长文件行数 | 1225（`atri_x/config/app_sections.py`） | ≤ 600 |
| 模块数 | 784 | ~650（合并微型模块，非强制） |

## 怎么拆（判定标准）

- **按职责拆**：先看这个文件有哪几个不相干的事实来源；每个来源一个模块。
- **拆完保留 facade**：原模块继续 re-export 被外部引用的符号，调用方零改动（这样一次拆一个，
  可以独立 review、独立回滚）。
- **拆完必须**：跑 `python scripts/gen_index.py` 更新索引；`check_docs.py --update` 收紧行数基线；
  跑相关测试。
- **不要**为了过指标而拆：预算指标是"防退化"，不是"逼重构"。
