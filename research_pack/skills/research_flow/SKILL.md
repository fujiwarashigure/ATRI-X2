# 流程调度（research_flow）

**这是整套科研流程的唯一"下一步"来源。** 只要开始或继续一个研究任务，先调它。

## 什么时候调

- 用户说"继续/下一步/到哪了" → `action=plan`；
- 刚执行完任何一步 → 再调一次 `action=plan`，确认状态推进；
- 想知道有哪些运行 → `action=list`；
- 想把计划落成人读文件 → `action=markdown`（写 `notes.md`）。

## 怎么用

1. `research_flow --action plan --run <id>`；
2. 只执行 `next[0].action`（`{tool, args}` 原样传给对应工具）；
3. 看返回的 `gate` / `blockers`：
   - `blockers` 非空 → 先按 `fix` 解除，不要绕过去做后面的事；
   - `gate=PASS` 且 `next` 为空 → 流程完成；
4. 每次执行完再调一次本工具，而不是自己记住"第几步"。

## 九步顺序（固定，不可跳）

检索 → 筛选 → 核验 → 引用 → 大纲 → 成稿 → 质检 → 评审 → 导出

## 为什么不用你判断顺序

弱模型最容易犯的错不是算错，而是**顺序错**：没筛选就写正文、没核验就导出、
反复重跑检索。顺序由产物存在性计算后，换任何模型都会得到同一份计划。

## 边界

- 不修改任何产物（只读产物、最多写 `notes.md`）；
- 计划里出现 `<...>` 占位参数时（如检索式），用用户的研究问题填，不要留空执行；
- 单轮只推进一个 ready 步骤，受宿主每轮 10 步限制。

## 工具契约（由引擎自动生成，勿手改）

- 工具：`flow` · 技能：`research_flow`
- 风险：`low`（普通成员可调用）
- 超时：60 秒
- 确定性：**是**——判定、排版、计数、门禁全部由引擎代码完成，不依赖模型自评。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `action` | 枚举(plan / markdown / list) | 是 | plan=返回计划（默认）；markdown=同时写 notes.md；list=列出全部运行。 |
| `run` | 字符串 | 否 | 运行 id；'latest' 表示最近一次。 |

结果里的关键字段：

- `next`：[{tool, args, why}]，只执行 next[0]，做完再调用一次本工具。
- `steps`：[{step, status: done|ready|blocked|todo, action}]，可据此向用户解释进度。
- `blockers`：[{code, message, fix}]，非空说明流程被硬条件卡住。

引擎强制执行的规则（不是建议）：

- 步骤顺序是常量（检索→筛选→核验→引用→大纲→成稿→质检→评审→导出），不由模型决定。
- 每一步的状态只由对应产物的存在性与闸门计算，同一份产物必然得到同一份计划。
- 有阻塞项时 gate=FAIL，next 只给出解除阻塞的动作；不允许跳步。
