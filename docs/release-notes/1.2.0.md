# ATRI-X 1.2.0 发行说明

1.2.0 是**执行面安全**版本：`shell` 与文件类工具默认进入**按用户安全域复用的容器**，
盒内允许折腾、盒外严格受控，联网默认可用但受网络层与出口代理约束，资源默认有界，
任务多了排队，环境坏了重建。配置格式向后兼容（新增 `[sandbox]` 字段，默认值即新行为）。

> 容器仍有共享内核等残余风险，本版**不承诺零逃逸**；它解决的是「别再拿命令黑名单当
> 沙箱」，不是「绝对安全」。完整说明见 [`docs/sandbox.md`](../sandbox.md)。

## 1. 默认执行面变了

旧状态（≤1.1.9）：`shell` 直接跑在宿主进程里，靠 AST 风险分级 + 逐条确认兜底；文件工具以
会话工作区（用户自选宿主目录）为根；没有资源硬顶、没有租户隔离、没有网络出站约束。

新状态（1.2.0）：`[sandbox].mode=container`（默认）时

- `shell` 在当前用户安全域的容器里执行，工作目录固定 `/workspace`，**盒内普通命令不再逐条
  确认**；AST 解析保留为提示/兼容用途，不再是安全边界。
- 文件 / 图片 / 发送 / `workspace` 工具解析到同一租户工作区；绝对宿主路径默认拒绝
  （`[sandbox].allow_host_files=false`，宿主文件访问是独立授权能力，不默认开放）。
- 后端不可用 / 隔离能力探测未通过 / 镜像缺失 → **拒绝执行**，绝不回落宿主 Shell
  （fail-closed）。
- 显式想回退旧行为：`[sandbox].mode="off"`（不安全，桌面端与 `/sandbox` 都会提示未保护）。

## 2. 用户安全域（租户）

默认租户键 = **平台 + 机器人账号/实例 + scope + 用户 ID**，不是只按 QQ 号：

- 同一个人在群 A 的任务数据不会带进群 B；同一部署的不同 bot 不共用环境；
- 不同租户的容器、内部网络、工作区、私有 home、缓存互不可见；
- 同一环境内的命令默认串行，避免两个任务互相改坏文件；
- 不活跃用户只保留限额内的数据（空闲回收 + 数据保留期），不长期占用运行内存。

## 3. 联网：默认可用，而不是默认废掉

| 档位 | 用途 |
| --- | --- |
| `offline` | 纯计算、文件处理、测试；容器 `--network none`。 |
| `public`（默认） | 日常联网任务：公网可用，宿主 / 内网 / 云元数据 / 容器引擎与运维端口被拒绝。 |
| `restricted` | 只允许 `restricted_hosts` 里的目标（支持 `*.example.com`）。 |

强制点在网络层与出口服务，不是环境变量：租户容器只接一个 Docker `internal` 网络（无默认
路由、无外部 DNS），唯一出口是同一网络里的出口代理；代理**先解析再按 IP 连接**（防 DNS
rebinding），禁止回环 / 私网 / 链路本地（含 `169.254.169.254` 等云元数据）/ CGNAT / 组播 /
保留段，以及 docker API、etcd、k8s、ssh、smtp 等管理/滥用端口。每租户每日流量额度、上下行
限速、并发连接数都有硬上限，到限后停止联网并返回明确原因；额度跨容器重建累计，**重置沙箱
不会清零**。

## 4. 资源与排队

- 内存硬顶（`--memory` 与 `--memory-swap` 同值，禁 swap 增长）、pids 上限、CPU 上限 +
  竞争权重（权重是忙时公平分配空闲 CPU，不是保底核数）、磁盘配额、命令时限、空闲回收、
  数据保留期；资源档 `light` / `standard` / `heavy` / `dsh`，重任务不塞进 512 MiB 档。
- 有界、公平、可取消的准入队列：交互优先 + 轮转 + 后台防饿死；拿到名额后才启动环境；
  等待有上限、可取消、可查状态；排队不占模型循环。

## 5. 生命周期与运维

- 三档重置：`restart`（重启，文件保留）/ `rebuild`（干净镜像重建，工作区 + 私有 home 保留）/
  `wipe`（清空全部文件并重建，**需要二次确认**）。流量、滥用记录与审计**不会**被重置清零；
  重置不能撤回已发出的消息或外部 API 写入。
- 聊天命令：`/sandbox`（状态 / reset / rebuild / `wipe confirm` / probe）。
- `/panic` 现在会额外**实际停止**全部沙箱环境。
- 桌面端「进阶」页新增**「沙箱管理…」**面板：刷新后端状态、运行隔离自检、环境列表、停止全部、
  保留文件 / 清空文件重置；后端未安装时明确显示不可用。
- 运维自检（源码与安装版一致）：`python -m atri_x.sandbox doctor`、`atri-x.exe -m atri_x.sandbox
  doctor --json`；另有 `status / list / probe / gc` 子命令。
- 审计记录租户、任务、镜像版本、资源档、网络档与退出原因，区分普通失败 / 排队超时 / OOM /
  磁盘超限 / 命令超时 / 后端故障；日志脱敏 + 轮转上限；崩溃/重启后首次执行前回收遗留容器。

## 6. 镜像与构建

- 内置可信基础镜像（`atri_x/sandbox/assets/Dockerfile`）：python-slim + git/curl/ripgrep/jq 等
  通用工具，不含 ATRI-X 运行时、`.env`、SQLite、QQ 登录态或模型凭据；
- 容器以非 root（uid 1000）运行、根文件系统只读、`--cap-drop ALL`、no-new-privileges、
  默认 seccomp；只挂工作区 / 私有 home / `/tmp` 三个可写面，均计入租户配额；
- 不挂宿主根 / 用户 home / 应用数据目录 / docker.sock；禁止特权与宿主 PID/IPC/network 模式；
- 镜像缺失时按内置 Dockerfile 自动构建（带内容指纹 label，改了 Dockerfile/代理源码会自动重建）；
  网络到 Debian 官方源慢时可在 `[sandbox].apt_mirror` 指定镜像源。

## 7. 兼容性与升级

- 配置向后兼容：旧 `app.toml` 不用改；`[sandbox]` 只新增字段，缺省即 1.2.0 行为。
- 数据 / 会话 / SQLite / 工具 schema 未变；会话工作区仍可用，但沙箱模式下文件工具只写租户工作区。
- 安装版直接覆盖安装即可；旧版 `data` 目录自动沿用。
- **运行前置**：Windows 上需要 Docker Desktop（WSL2 后端）或可用的 Podman；两者都没有时
  `shell` 会明确报「沙箱不可用」而不是退回宿主。离线/受限环境可先用 `offline` 档。

## 8. 验收（本版实测）

- 全量单元测试 **7495 项通过**（9 项按环境跳过；真 Docker 集成测试用 `ATRIX_SANDBOX_IT=1`
  单独跑）；11 道静态门禁全绿。
- 真 Docker 冒烟：`curl https://example.com` 200；直连 `1.1.1.1:443` 失败；
  `http://169.254.169.254/` 经代理 403；`sleep 600` 超时后环境自动重建可用。
- 双租户隔离验收：同群两人、同人两群互读不到工作区文件；容器内无 docker.sock、
  读 `/etc/shadow` 被拒、uid=1000、三个独立容器。
- 安装版：`atri-x.exe --version` → `atri-x 1.2.0`；`-m atri_x.sandbox.doctor --json` 全部通过；
  `config check`、GUI selftest、便携版启动与安装/卸载自检通过。完整证据见发行库
  `自检报告.md` 与 `证据/1.2.0/`。

## 9. 已知边界（不隐瞒）

- DSH 执行链在沙箱模式下被**限制**（请求回落沙箱内原生工具），控制进程/子进程/模型密钥
  尚未完成租户隔离，本版不宣称密钥隔离完成；
- 任务新生成的 Skill / 插件「进候选区、不热加载宿主」、渲染器进容器、快照/检查点/自动恢复、
  Windows 原生 AppContainer 后端均属后续批次；
- 有网不等于「半个宿主」，但公网出站仍可能被用于外传任务可见数据或滥用公网服务
  （有配额、限速、审计与停用能力，不是零风险档）；
- 容器共享宿主内核；只读挂载仍受权限控制；「拿到名额才启动环境」意味着高并发时会排队。
