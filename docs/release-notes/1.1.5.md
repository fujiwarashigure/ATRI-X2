# ATRI-X 1.1.5 发行说明

1.1.5 只做一件事：把**可编辑架构图**做成产品能力。超管在聊天里说"把这个项目的模块依赖画出来"
"把 `infra/` 的 Terraform 画成部署图""把这坨建表 SQL 画成 ERD"，机器人就能生成
`.drawio` 并用**随包内置的 draw.io 32.6.1** 渲染成 PNG 直接发到群里——不需要用户装 draw.io，
不需要 Python，也不需要联网。

## 一、新能力：内置 draw.io 图表（仅超管）

- **一个工具 `drawio`，9 个动作**：`build`（代码目录 / Terraform / SQL / OpenAPI / AsyncAPI /
  Proto / GraphQL / K8s / Compose / CI，共 15 种来源）、`create`（Diagram IR / graph JSON /
  手写 XML）、`export`（PNG / SVG / PDF）、`validate`（结构校验 + 连线质量评分）、
  `inspect`（结构摘要 / 无障碍文本）、`query`（按 kind/owner 过滤、查两节点有向路径）、
  `shapes`（检索 draw.io 官方形状 style，避免模型臆造）、`docs`（20 篇内置参考文档）、
  `doctor`（渲染器/依赖自检）。
- **可编辑，不是图片**：交付物同时包含 `.drawio` 源文件与渲染图；后续可让人工在 draw.io 里继续改，
  也可以把源码改了重新生成。
- **视觉自检闭环保留**：渲染出的 PNG 会作为图片消息回到聊天，模型自己也能看到图，检查重叠、
  截断、连线穿节点，最多两轮针对性修复。
- **随包 AgentSkill**：上游 [drawio-skill 3.4.2](https://github.com/Agents365-ai/drawio-skill)（MIT）
  的 47 个纯标准库脚本、20 篇参考文档、官方 shape 索引原样随包（`drawio_pack/`），首次启动装进
  `<配置目录>/ATRI-X/skills/agent/drawio_skill/`；上游 247 个回归测试作为一致性门禁。
- **内置无头渲染器**：draw.io 桌面版 32.6.1 解包目录放在产物 `_internal/drawio_runtime/`，
  渲染时以无窗口模式调用，单页约 3 秒，**不读写宿主机上用户自己的 draw.io 配置**。
- **权限**：清单 `superadmin_only = true`——普通成员**连工具 schema 都拿不到**；群聊
  `tool_allowlist` 也不会对普通成员放开。

## 二、体积与性能

| 项 | 1.1.4 | 1.1.5 | 说明 |
|---|---|---|---|
| 安装包 / 便携 zip | 见上一版发行说明 | **便携 zip +181 MB、安装包 +133 MB**（压缩后实测） | 内置 draw.io 桌面版（解包 449.9 MB → 随包约 382 MB，删了 53 个语言包；`ffmpeg.dll` 必须保留） |
| 源码归档（repo zip） | 见上一版 | **增加约 1.2 MB** | 只含技能本体；渲染器是构建材料（`packaging/vendor/`，不入库） |
| 运行时内存 / 启动 | 不变 | 不变 | 渲染器只在调用 `drawio` 工具时启动，用完退出 |

- 单页 PNG 渲染实测约 3 秒；并发 3 路导出实测通过（共享 profile 不冲突）。
- 中文 / 空格路径、非法输入（快速报错、不弹窗卡住）、多页导出（`pages=all`）均实测通过。
- 产物文件写在技能目录 `out/`，只保留最近 60 个；不会往用户桌面或其他目录乱写。

## 三、兼容性

- **配置格式不变**：没有新增配置段；`drawio` 工具自动出现（仅超管可见），旧配置直接可用。
- **会话 / 数据库格式不变**：没有改动会话、消息、工具调用或审计表结构。
- **安装版 / 便携版**：首次启动自动安装技能（失败只记 WARN，不影响机器人启动）；无需任何手工步骤。
- **源码树**：默认**不**自动安装（避免开发/测试写真实配置目录），需要显式启用：
  ```bash
  python -m atri_x.diagram.bootstrap --source       # 装进默认配置目录
  python -m atri_x.diagram.bootstrap --status       # 看状态
  ```
  源码树渲染需要把 draw.io 解包目录放到 `packaging/vendor/` 下的 drawio 子目录，或设置 `ATRIX_DRAWIO`。
- **Docker 镜像**：镜像不带 Electron，**不提供** PNG/SVG/PDF 渲染；生成/校验/检索/文档动作可用
  （Glob 形态的部署请以超管在 Windows 机器上出图为准）。

## 四、已知限制

- 无窗口渲染依赖**交互式 Windows 会话**：以服务方式跑在 Session 0 / 无桌面环境时导出会失败，
  并**降级**为只交付 `.drawio` 源文件；其余动作不受影响。
- 一期只注册上表 9 个动作；上游的 `sync` / `reconcile` / `views` / `test` / `review` /
  `whatif` / `story` / `transform`（PPTX、Mermaid、动画等）脚本随包但暂未注册为动作，
  需要时由超管在服务器上直接运行。
- 图里的内容会随聊天外发：`build` 会把源码/IaC/表结构/接口里的名称与属性写进图，
  导入前请确认这些内容可以外发（详见 [LEGAL.md](../../LEGAL.md) §五）。

## 五、怎么验证

- 单测：`python -m unittest tests.test_diagram_pack tests.test_diagram_skill tests.test_drawio_pack_upstream`
  （随包资源 / 适配器动作 / 上游 247 个回归）。
- 产物级：`python packaging/build.py --verify-only`——会装技能、检查
  `_internal/drawio_runtime/draw.io.exe`、在冻结进程里跑 `doctor`，并**真实导出一张 PNG**。
- 手动：安装版启动后，用超管 QQ 说"画一张你的系统架构图，两个节点就行"，应收到一张 PNG 与
  一份可编辑 `.drawio`。

## 六、1.1.5 修订（版本号不变）

首次构建后补的一批修复，仍然是 1.1.5：

- **生图「获取可用模型」401**：界面里刚填、还没保存的密钥现在会**优先用于**这次请求；
  完全没带密钥时提示改成"先保存进阶配置再获取"，不再误报成"密钥配错"。LLM Provider 的
  「获取可用模型」与本地生图服务探测同样处理。
- **`/status` 的「命中」不再恒 0**：上游没返回缓存字段时显示 `命中：未上报`（未知≠0），
  上游明确返回 0 时才是 `命中：0`；这个区别会随会话落库，重启后不变。
- **审计/用量统计恢复**：修复了生产装配里日志与审计通道没接线的问题（`audit-*.log` 不再为空），
  `/usage`、`/log`、安全审计与每轮 `llm_usage` 事件都有数据；每轮另记一条 `usage recorded`
  （含缓存是否上报），方便核对 token 与命中。
- **请求日志格式修复**：请求摘要与首个 system prompt 不再输出成 `%s %s =!BADKEY`。
