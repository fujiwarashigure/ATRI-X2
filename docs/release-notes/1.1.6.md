# ATRI-X 1.1.6 发行说明

1.1.6 做三件事：**提示词系统可以在桌面端自己改**、**群聊能变成一页漫画**、以及修掉
便携版「下载头像」的 HTTP 400。

> **2026-10-31 重发（版本号仍为 1.1.6）**：修掉一个协议端托管状态误报——
> 桌面端「在线」页会把本程序刚启动的 NapCat 显示成
> 「进程：未运行或未托管（PID … 已被别的进程占用（cmd.exe））」，且「停止协议端」
> 拒绝执行（`cmd /c Start-NapCat.bat` 记录的镜像名是 `cmd`，`tasklist` 报 `cmd.exe`，
> 字符串比较把"自己起的进程"误判成"PID 被别的进程复用"）。现在镜像名会先归一化
> （去路径 / 转小写 / 去 `.exe`）再比较，旧记录也能对上；真正被复用的 PID 仍然拒绝。
> 只影响托管状态显示与「停止协议端」，启动、扫码登录与协议端本身不变。
>
> **同日第二次重发**：再修一个"QQ 登录成功，但 ATRI-X 永远连不上协议端"的故障——
> 内置 NapCat 的 OneBot 端口 `3001` 可能落在 **Windows 的排除端口段**（Hyper-V / WSL /
> Docker 保留，本机实测 `2942–3041`，绑定报 `WinError 10013`），NapCat 于是能登录 QQ
> 却监听不上，「在线」页一直是「协议端未就绪」、后台日志只有
> `连接 ws://127.0.0.1:3001/ 失败：[WinError 1225]`。现在桌面端准备配置时**先探测端口
> 能不能绑**：被保留 / 被占用就自动顺延到可用端口，同步改写 `onebot11.json`、登录后
> 优先生效的 `onebot11_<QQ号>.json` 与 `app.toml` 的 `ws_url`，「在线」页会写明原因
> （如「端口 3001 不可用…已自动改用 30001」）。已有协议端在监听时不动端口，避免把在线
> 机器人踢下线；指向外部协议端的非回环 `ws_url` 一律不覆盖。
>
> **同日第三次刷新（只动 CI / 测试 / 源码归档，安装包与便携版逐字节不变）**：全量单测在
> 托管 runner 上要跑 45 分钟以上，反复以 `The hosted runner lost communication with the
> server` 失败（步骤停在 `in_progress`、job 已结束），质量门禁常年红。现在按模块实测耗时把
> 7,167 个用例**确定性拆成 6 片并行**（`scripts/ci_shard_tests.py`，
> `scripts/ci_test_weights.json` 记录逐模块耗时），单片约 6–10 分钟，
> 门禁与单测是两个并行 job，runner 固定 `ubuntu-24.04`；同时修掉一条依赖构建机是否放了
> draw.io 渲染器（400 MB，不入库，构建时用 `--with-drawio` 指定）的用例（打桩渲染器目录，
> 只测「PIL 校验早于 PyInstaller」）。因此只重出源码归档（1,459 条目）与 `SHA256SUMS.txt`，
> 两个安装产物仍是上一轮的字节。

## 一、提示词系统：GUI 里改，不用改代码重新打包

以前提示词分四层：`SOUL.md` / 人设卡 / 群友档案 / 生图预设这些"用户数据"能改，但
**模板常量写死在源码里**——生图改写的两套 system 教义、识图四套模板、群友档案与专属人设的
注入模板、表情提示、人设卡指引，想改只能改 Python 再打包；`[image_generation.profiles.*]`
（`@image:<名字>` 命名生图档案）与 `tool_tags.toml` 的 tag 提示词也只能手写 TOML。

现在：

- 桌面端新增第 15 个「提示词」选项卡，四个子页：
  - **提示词模板**：分类列表 + 正文编辑 + 示例变量预览 + 恢复默认 / 导入 / 导出；
    内置 11 条（生图改写、识图四套、群友档案、专属人设、表情提示、人设卡指引、漫画分镜）；
  - **生图档案**：`[image_generation.profiles.*]` 增删改，写回 `services.toml` 且保留其它键与注释；
  - **工具标签**：`tool_tags.toml` 的 tag → 工具组 + 提示词；
  - **标签库**：标签词表（名称 / 说明 / 别名 / 分组）。
- 用户覆盖写 `<配置目录>/gui/prompts.json`，**只存和默认不同的条目**：升级内置模板时，
  没改过的条目自动跟随新默认。按 `(mtime_ns, size)` 指纹热加载，保存后**下一轮对话生效**。
- 群友页 / 人设卡页的「标签」输入框旁新增「标签库…」多选按钮；群友档案注入时命中词表的
  标签渲染成 `标签（说明）`，未登记标签原样输出（旧档案不受影响）。
- 用户自建提示词可勾选「注入系统提示词」，作为独立片段追加到每轮系统提示词。
- 默认行为与 1.1.5 **逐字一致**：内置模板文本原样搬进 `atri_x/promptlib/defaults.py`，
  测试逐字断言；群友档案自由文本的 `<` / `>` 转义仍由代码强制，模板不能绕过注入边界。

## 二、聊天漫画：`comic_plan` / `comic_render`

想让机器人"根据刚才聊天画六格漫画"，以前只能靠 `image_generate` 加成句提示词：上下文是
压缩摘要（没有消息 ID）、没有结构化分镜、台词可能被改写。现在新增两个工具：

- `comic_plan`：把**当前群聊**改编成结构化分镜——格数、人物、逐字台词、来源消息 ID 全部
  落成计划，返回 `plan_id` 与逐格预览。**不调用生图接口、不扣额度**。
- `comic_render`：按 `plan_id + revision` 生成**一张整页**漫画（不是每格一张）。计划更新后
  旧版本会被拒绝，避免"改了台词却拿到旧图"。

要点：

- **来源可查**：只从当前会话取材；锚点不存在或聊天不足时明确报错，不编造来源；每格台词都能
  追溯到消息 ID，区分原文 / 缩写 / 创作台词。
- **人物不串**：群友身份用 `member:<platform>:<sender_id>`，角色卡用 `character:<id>`；
  参考图优先级「本次显式指定 > 角色卡图片 > 平台头像」，用户说"就用头像"时不会被换成角色卡，
  缺图明确告警或报错。
- **台词不丢**：漫画不走普通生图的语义改写通道，分镜 / 逐字台词 / 人物—参考图映射都是受保护
  提示词块；超长时先丢风格片段、仍超长直接报错，不静默丢分镜。
- **失败不乱重试**：生成 / 入库 / 投递是三个独立状态；超时等"可能已生成"记为结果未知，不自动
  重试；投递失败用 `task_id` 重发已有图片，不重新扣费。生成记录保存在
  `<配置目录>/comic/`（计划与任务各一份 JSON，可解释"这张图怎么来的"）。
- **复用现有设施**：与 `image_generate` 共用同一批生图 profile、并发限流、Media Center 与内容
  安全检查，没有第二份 HTTP 客户端；生图 profile 的 `superadmin_only` 在漫画层重新校验。
- **规划模型可选**：`[comic].planner="auto"` 时有模型用模型、没模型用规则规划（规则规划的台词
  逐字取自聊天原文，开箱可用）；漫画分镜提示词也能在「提示词 → 漫画」里改。

配置（`services.toml`，有默认值、缺段也能用）：

```toml
[comic]
enabled = true
planner = "auto"          # auto | rules | llm
plan_model = "work"
default_panel_count = 6
max_panels = 12
max_characters = 4
max_prompt_runes = 6000
send_by_default = true
```

完整说明见 [聊天漫画](../comic.md)。

## 三、修复

- **桌面端「群友」页「下载头像」HTTP 400**：QQ 头像接口只接受固定边长档位
  `40 / 100 / 140 / 640`，界面原先把本地缓存边长 `96` 直接当请求参数，服务端回
  `HTTP 400`（`X-ErrNo: -105`）。现在请求边长先吸附到接口支持的档位，本地仍按 96 缩放缓存。
- 顺手修了测试隔离：`test_app_runtime_agent` 构造 Agent 时安装的进程级旁路用量 sink 会残留到
  后续测试，导致无关用例（压缩摘要）偶发 `AttributeError`；模块收尾时清理。

## 四、兼容性

- **配置向后兼容**：新增 `[comic]` 段（缺段用默认值）；提示词覆盖存在新文件
  `<配置目录>/gui/prompts.json` / `gui/tags.json`，旧配置无需改动。`[comic]` 只认
  `services.toml`，写进 `app.toml` 会被严格解码拒绝。
- **会话 / 数据库格式不变**：漫画的计划与生成记录是普通 JSON 文件，不涉及数据库迁移。
- **桌面端**：15 个选项卡（新增「提示词」）；「工具权限」页会看到 `comic_plan` /
  `comic_render` 两个新工具。
- **安装版 / 便携版**：内置 DSH 内核、内置 QQ 协议端（NapCat）与内置 draw.io 渲染器保持不变；
  安装包为用户级安装（不弹 UAC）。

## 五、已知限制

- 漫画只保证「请求里的台词不丢、不改写」；绘图模型能否逐字画对中文台词取决于模型能力，
  需要人工 E2E 验收。
- 一页最多 4 个有参考图的人物（与生图参考图上限一致）；更多人物请分页。
- 首版是"一张图包含全部格子"；逐格生成再拼版、局部重绘、中文后期排版不在本版范围。
- 桌面端暂未给漫画策略单独做配置页（在 `services.toml` 的 `[comic]` 段配置）。
