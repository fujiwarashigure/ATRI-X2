# ATRI-X 1.1.7 发行说明

1.1.7 是一个**稳定性补丁版**，做四件事：**桌面端断线自愈**（后台服务没了会自己拉起来）、
**服务退出可诊断**（gui.log 里能查到服务是怎么没的）、**修掉 Linux/Docker 上 hook 插件超时
会杀掉整个服务的进程组 bug**、以及**测试/CI 卫生**（本地跑全量单测不再需要先停掉你正在用的
后台服务）。不改配置格式、不改工具 schema、不改会话与数据库格式，直接覆盖安装即可升级。

## 一、修掉「桌面端经常掉线且不会自己恢复」

**旧状态（1.1.6）**：桌面端只是 WS 前端，Agent 跑在独立的 `atri-x service run` 里。后台服务
一旦消失（崩溃、被安全软件/优化工具清理、被脚本误杀、系统回收），GUI 只会每 2 秒重连一次，
状态栏永远停在「已断开（… WinError 1225）」，**不会自己把服务拉起来**；QQ 机器人和桌面端
一起长期掉线，必须手动点「服务 → 启动/确认后台服务」。更糟的是服务消失时没有任何线索：
stdout 日志通常什么都没有，只有一个谁也看不见的退出码。

真实事故：本地跑全量单测的人为了让部署探针用例通过，先杀掉了正在使用的后台服务腾出
`127.0.0.1:32171`，测试跑完忘了重启——桌面端就一直显示「已断开」。

**新状态（1.1.7）**：

- **断线自愈**：连接断开持续 8 秒后，桌面端自动探测一次；进程还活着但端口不通就先结束它
  （挂死的服务重启才能好），然后拉起 `atri-x service run` 并等就绪，就绪后自动重连。状态栏
  在恢复期间显示「正在自动重启后台服务…」。
- **退避与上限**：失败按 15 / 30 / 60 / 120 秒退避，一次掉线最多尝试 5 次；用尽后提示从
  「服务 → 重启后台服务」手动恢复，不会无限刷屏式重启。
- **安全边界**：只对 `ws://127.0.0.1`、`localhost`、`[::1]` 的本地服务启用——连远端服务器时
  绝不替对方重启进程；`--no-service`（只连已有服务）与用户显式点「停止后台服务」之后都不会
  自动拉起（不跟用户的意图打架）；用户点「重启后台服务」的 1–2 秒断连窗口也不会触发自愈。
- **退出可诊断**：每次后台服务的启动/退出都写进 `<配置目录>\gui\gui.log`，包含 pid、退出码
  与运行时长（例如 `后台服务退出（pid 38580，退出码 1，运行 842s）`）。下次再遇到「服务悄悄
  没了」，打开这个文件就能知道是什么时候、以什么方式退出的。

## 二、Linux / Docker：hook 插件超时不再把整个服务杀掉

**旧状态（1.1.6，只影响 POSIX）**：hook 插件（`exec` 动作、有状态 hook worker）超时或停止时，
清理代码用 `os.killpg(os.getpgid(子进程))` 杀整棵进程树，但子进程和宿主在**同一个进程组**里——
于是「插件超时」实际打中的是 ATRI-X 服务自己，进程被 SIGKILL 整机掉线；CI 分片 runner 也会
因此被 SIGKILL（job 一直 `in_progress`、日志都拿不到）。

**新状态（1.1.7）**：插件进程在 POSIX 上用 `start_new_session=True` 启动、自成进程组，超时
清理只命中插件自己的那棵树；杀进程组前还有一道防御性守卫——**绝不朝宿主自己所在的组开枪**。
Windows 行为不变（`taskkill /T /PID`）。

## 三、测试与 CI 卫生（不影响运行行为）

- **本地全量单测不再需要停后台服务**：部署探针用例过去默认访问 `127.0.0.1:32171` 并断言
  「连不上」，本机后台服务正常监听时会打到真服务上误报失败；现在探针与启动器用例显式指向
  一个空闲端口，测试与宿主上跑着什么无关。
- **CI 全量单测拆 6 片并行**：7,167 个用例按实测耗时切成 6 个分片（`scripts/ci_shard_tests.py`
  + `scripts/ci_test_weights.json`），门禁与单测分成两个 job；此前单进程跑 45 分钟以上会
  被 GitHub 托管 runner 判定失联。
- **修掉只在 ubuntu 上失败的 6 个平台专有断言**：Windows 路径语义（`file:///C:/…` 前导斜杠、
  协议端记录里的反斜杠路径、`.iss` 里的反斜杠路径）、视觉字节预算用例依赖 Pillow 压缩率、
  `/diagnostics` 把 `pillow_installed` 写死为 True——现在的断言与平台无关。

  覆盖 / 索引 / 统计 / drawio 包 / 文档 / 复杂度 / CI 分片计划。
- 全量单测：`Ran 7,192 tests`，失败 0 / 跳过 4（3 个是本机没有 Tk 显示环境的图形用例，1 个是

  服务，本版不需要了）。

### 发行物重发（2026-10-31）

本轮发行物在源码不变（tag `v1.1.7` 未动、源码归档仍为同一条提交）的前提下**重建过一次**：
审计发现内置 QQ 协议端的构建输入里残留一个 NapCat 运行期生成的 `guild1.db`（192 KB，
含一条 QQ NT 内部账号标识，非令牌/登录态/ATRI-X 用户数据），它从更早版本起就被随包复制。
现已从构建输入中删除该运行期文件并重新出包，产物哈希随之更新（上表与 `SHA256SUMS.txt` 为
重发后的值）；安装包负载与便携包负载仍逐文件一致，其余产物（源码归档、条目清单）不变。
- 注：杀服务后自动恢复的现象依赖新装上的 1.1.7 桌面端（1.1.6 没有自愈）；行为本身由
  `tests/test_gui_supervisor.py` 的 23 条用例覆盖，`gui.log` 里能看到「后台服务退出（pid /
  退出码）」与「后台服务已自动恢复」两条记录。
