# ATRI-X 1.1.4 发行说明

1.1.4 是两个主题一起发：一个**用户能直接感知的新能力**（超管查本机资源占用），以及一套
**让仓库不再"文档一漂就归零"的工程设施**（生成索引 / 文档门禁 / 复杂度预算 / CI）。
后者不改任何业务行为，但决定了以后每一次改动的成本。

## 一、新能力：超管专属硬件资源查询

- **新工具 `runtime_resources`**（`superadmin_only` + `risk=safe`，只读无副作用）：一次调用拿到
  CPU / 内存 / 磁盘 / 显卡占用与型号（CPU 型号、GPU 型号与显存、系统版本）、进程内存（RSS / 峰值 /
  私有提交）、进程 CPU（单核基准）、线程与句柄数、读写字节、进程运行时长，以及整机 CPU / 内存 /
  开机时长。采样窗口默认 500ms（可调 100–2000ms）。
- **新命令 `/resources`**：确定性入口，不必等模型排到那一轮，也没有转述误差；与工具共用同一份渲染。
- **显卡占用**：NVIDIA 有 `nvidia-smi` 时按卡报利用率 / 显存 / 温度 / 功耗；AMD / Intel（以及没有
  `nvidia-smi` 的 NVIDIA）走 Windows 性能计数器（PDH `\GPU Engine(*)\Utilization Percentage`），
  报整机 3D 引擎占用。两者都不需要用户额外安装工具（`nvidia-smi` 本身随 NVIDIA 驱动分发）。
- **隐私（1.1.4 修订）**：早期版本会把"配置目录所在卷"的**真实路径**（例如
  `C:\Users\<用户名>\AppData\Roaming\ATRI-X`）渲染出来，等于把用户名与目录结构报给群聊。现在磁盘
  只报**卷标签**（`系统盘` / `数据盘 N`），CPU / GPU 只报型号与占用，**不回显路径、用户名、主机名**；
  采集失败的描述只保留异常类型名（异常原文可能带路径）。命令与工具共用
  `atri_x/sysinfo_format.py` 这一处渲染，隐私边界不会漂移。
- **权限**：走现成的双闸门（发现阶段 + 执行阶段）——非超管**连 schema 都拿不到**，模型不会瞎编数字。
  群聊里若配过 `tool_allowlist`，需要把 `runtime_resources` 加进去。
- **修好一个长期问题**：`atri_x/sysinfo.py` 的 `process_rss()` 在 Windows 上**恒返回 0**（只实现了
  Linux 的 `/proc` 分支），导致 `/metrics` 的 `resources` 段与定时日报在 Windows 上一直显示 0。
  1.1.4 用标准库 `ctypes` 调 kernel32 补齐（`K32GetProcessMemoryInfo` / `GetProcessTimes` /
  `GetProcessHandleCount` / `GetProcessIoCounters` / `GlobalMemoryStatusEx` / `GetSystemTimes`），
  并把进程级与系统级采样抽成可注入的 `PlatformCollector`，测试不需要真实 Windows API 与真实计时。

数据来源与口径、Windows ctypes 的五个坑、以及"为什么不能用 psutil"见
[改造清单式的实现说明](../configuration.md) 与 `atri_x/sysinfo.py` 的模块注释；硬件/显卡的采集拆分见
`atri_x/hardware.py`、`atri_x/gpu_usage.py`、`atri_x/sysinfo_platform.py`。

## 二、工程设施：让文档与索引变成可执行产物

### 1. 生成式索引（第二支点之一）

新增 `atri_x/devtools/`（AST 索引 + 渲染 + 入口 + 域文档，**零第三方依赖、不 import `atri_x`**）与
`scripts/gen_index.py`，生成 **16 个产物**：

| 产物 | 内容 |
| --- | --- |
| `devdocs/generated/module-map.md` | 每个模块 → 一句话职责 / 公共符号 / 行数 / 测试文件 |
| `devdocs/generated/deps.mmd` | 二级域依赖图 + 域依赖矩阵 |
| `devdocs/generated/entrypoints.md` | 进程入口 / 装配层 / 命令 / 工具 / 平台 / Hook / GUI / 任务入口 / 文档锚点 |
| `devdocs/generated/test-map.md` | 模块 ↔ 测试双向表，并显式列出**没有任何测试直接覆盖**的模块 |
| `devdocs/generated/go-map.md` | 模块 → 上游 Go 文件，并校验 `PORTING.md` §4 每条映射仍成立 |
| `atri_x/<域>/README.md` ×10 | 域职责 / 不做啥 / 易错点（人工数据）+ 模块清单 / Go 映射 / 测试（生成） |
| `docs/dev/glossary.md` | 中文功能名 ↔ Python 域 ↔ 上游 Go 包 ↔ 配置段 |

`python scripts/gen_index.py --check` 在 CI 里比对"重新渲染的结果"与磁盘产物：**改了代码忘了跑
生成器**和**手改生成物**都会红灯。文档从"软副本"变成"编译产物"。

### 2. 文档门禁 `scripts/check_docs.py`（6 条断言 + 2 个棘轮）

相对链接可达 / 内联路径存在 / 索引覆盖全部模块 / locator 锚点不重复且有定义 /
行数预算只降不升 / 数字与实测一致。带 `--update`（重冻结基线）与 `--list`（实测计数）。

### 3. 结构预算 `scripts/check_complexity.py`

把结构指标冻结成"只降不升"：模块数、超 600 行文件数、最长文件行数、跨一级域 import 边、
最大 fan-in、无测试触达模块数、**跨域绕开枢纽 facade 的次数**（`atri_x/devtools/boundaries.py`）。
放宽预算必须改 JSON —— 一次在 review 里看得见的动作。

### 4. CI

新增 [`.github/workflows/quality.yml`](https://github.com/fujiwarashigure/ATRI-X2/blob/main/.github/workflows/quality.yml)：
7 道代码门禁 + 生成索引 `--check` + `gen_stats --check` + 文档门禁 + 复杂度预算 + 全量测试。
**在此之前，7 道门禁从未在 CI 跑过**（只有发镜像的 workflow）。

### 5. 人的入口（不再写第二份知识）

  `module-map.md`；
- 新增 `docs/dev/START-HERE.md`（30 分钟上手 + 三个练习）、`docs/dev/find-it.md`（10 类任务的
  文件级步骤与易错点）、`docs/dev/glossary.md`、`devdocs/adr/` 的 0001–0004（平铺 / 600 行 / 零依赖 /

## 三点五、顺手修掉一个存储层真 bug

稳定性测试期间发现：`format_time` 按 Go `RFC3339Nano` 的规则去掉小数秒末尾的 0，于是同一秒内
可能同时出现 `…:45.7835Z`（783500µs）与 `…:45.783545Z`（783545µs）。直接按**字符串**比较
（SQLite 里就是这么排的）时，前者的 `Z`（U+005A）大于后者的 `4`（U+0034），导致**较早的消息
排到后面**——实测同一会话的 user / assistant 次序约 0.5% 概率颠倒。

修复：**不动存储格式**（仍是 RFC3339Nano，与 Go 一致），只在查询侧用
`rtrim(created_at, 'Z')` 归一化比较（`atri_x/storage/times.py:order_time_expr`，应用到消息列表 /
会话预览 / 上下文摘要三类查询），并补了一条确定性回归用例
（`tests/test_sqlite_store.py` 的 `test_list_by_session_orders_same_second_variable_precision`）。

## 四、兼容性

- **不改**配置格式、工具 schema、会话与数据库格式；配置与会话数据向后兼容。
- 工具数 54 → 55（新增 `runtime_resources`）、命令数 49 → 50（新增 `/resources`）；依赖注册表计数的
  断言已同步（这是刻意的回归保护）。
- `atri_x/sysinfo.py` 的 `collect()` / `Snapshot` 语义不变（日报 / `/metrics` / diskguard 零改动），
  只有 Windows 上 `process_rss()` 从"恒 0"变成真实值。
- 新增 `atri_x/devtools/` 会被 PyInstaller 的 `collect_submodules("atri_x")` 收进冻结包；它零第三方依赖，
  不会改变产物体积的量级。

## 五、验证

- 全量 `unittest`、7 道代码门禁、`gen_index --check`、`check_docs`、`check_complexity` 全部通过；
- 性能冒烟：`/resources`（工具与命令两条路径）在采样窗口 500ms 下的耗时、事件循环不被阻塞；
- 稳定性：多次连续采样 + 并发调用不泄漏句柄、不增长 RSS；
- Windows 冻结产物上实测 ctypes 采样（`ctypes` 在 PyInstaller 下不需要额外 hiddenimport）。

产物尺寸与 SHA-256 见同批发布的 `SHA256SUMS-1.1.4.txt`、`自检报告.md` 与兼容性报告；对应 tag 为 `v1.1.4`。
