# ATRI-X 1.1.8 发行说明

1.1.8 有两条主线，外加一个安装版体验改动，**都不改会话与数据库格式**：

1. **内容安全彻底升级**：从"进程内词表 + 宽正则"升级为**用户可编辑的数据目录 + 热加载 +
   远程双供应商 + 三档裁决（放行 / 待复核 / 拦截）**，并且把入站媒体、模型输出、发送边界、
   生图提示词都接进同一条审核线。
2. **DSH（深度任务路由）真正可用**：修掉"每轮白付一次冷启动再吃 404"的凭据协议问题、
   补齐有界并发 / 忙时回退 / 卡死看门狗 / 预热与空闲回收 / 会话亲和 / 网关头代理。
3. **安装版可选「数据与配置目录」**：安装时可把配置、会话库、DSH 状态、技能与日志放到
   安装目录下（自包含、整个文件夹可拷走），并自动迁移旧的 `%APPDATA%\ATRI-X` 数据。

配置向后兼容：1.1.7 的 `app.toml` / `services.toml` / `state.toml` 原样可用；新增项都是
可选的（不写就沿用 1.1.7 行为）。升级可直接覆盖安装 1.1.7。

## 一、内容安全：从"写死的 54 条词表"到可运营的审核体系

**旧状态（1.1.7）**：内容安全只是"进程内词表 + 宽正则"的单层过滤器——8 类词表共 54 条中文
词条（子串匹配、无归一化），10 类敏感信息正则；词表与正则打在包内，用户改不了、改完要重启、
升级会被覆盖；只有放行 / 标记 / 脱敏 / 拦截四档，没有"待人工复核"的中间档；没有远程/语义
审核，无法判断语境；图片与文件只做出入口整体丢弃，不做内容识别。实测在一台真实实例上，
11 条审计**全部来自工具结果，11/11 都是误报**，其中 5 条"脱敏"真的改写了搜索/网页内容。

**新状态（1.1.8）**：

- **数据目录 + 热加载**：新增 `<配置目录>/safety.toml`、`safety/wordlists/*.txt`（与内置词表
  合并、新文件名自动成为新类别）、`safety/sensitive/*.regex`、`safety/scopes/*.toml`（按群 /
  按用户覆盖）。按文件指纹热加载，改完保存即生效（通常 ≤1 秒），不需要重启；坏配置会保留
  上一份可用策略并告警，不会静默失效。
- **本地层升级**：词表匹配先做归一化骨架（NFKC、去零宽 / 变体选择符、去 CJK 间分隔符、
  大小写折叠），`制 毒` / `ｍｉｎｏｒ` 这类绕过写法不再漏；扫描预算放宽到 4 倍（分块），
  超长工具结果不再只检查开头。
- **三档裁决**：`block` / `review` / `pass`。`review` 默认"照发 + 入队"（高敏群可配 `hold`
  先压住），人工队列落 `<配置目录>/safety/review.db`（状态机 `pending → approved / rejected /
  expired`），桌面端「内容安全 → 复核」页可直接处理。
- **按群 / 按工具差异化**：`[tools]` 配某工具的远程策略（`sync` / `cache_only` / `local_only` /
  `off`），`safety/scopes/*.toml` 按 `platform + scope_id` 覆盖失败策略 / 图片模式 / 强制或
  豁免工具 / 档位映射。工具结果默认只走本地层（这正是 1.1.7 的误报重灾区）。
- **远程审核层（腾讯云 + 阿里云）**：TC3-HMAC-SHA256 / ACS3-HMAC-SHA256 用标准库手写，不引
  SDK；双供应商按 `quorum`（`any_block` / `both_pass` / `primary_only`）仲裁，主供应商失败
  自动切备；熔断（连续 5 次失败冷却 60 秒、认证错误冷却 10 分钟）、内容级缓存（TTL + LRU）、
  当日预算熔断（`daily_budget_cny`）。凭据只从 `.env` 读。
- **多模态与双向审核**：图片同步送审（本地字节 base64；超阈值且有对象存储时走 URL）；语音
  先审 ASR 转写文本；音视频走异步任务（轮询后续接入）；入站文本 / 入站图片、模型输出、发送
  边界（正文 / 通知 / 图片 / 文件）、生图提示词都接在同一条 guard 线上。远程审核开启时关闭
  流式（`stream.append` 的 delta 无法事后收回），宁可没有打字机效果也不发未经审核的正文。
- **失败开放 / 关闭**：`fail_mode = "open"` 默认"放行 + 告警 + 审计标 `fail_open`"；
  `fail_close_scopes` 或 scope 文件可把高敏群改成"拦"。
- **留痕 v2**：审计每行多 `schema=2` / `tier` / `provider` / `request_id` / `score` / `degraded`
  / `fail_mode` / `latency_ms` / `hold`，仍然只存 `sha256` + 脱敏预览。
- **桌面端「内容安全」页**（六个子页）：总览 / 策略 / 词表 / 复核 / 审计 / 原始 TOML。词表与
  正则可在线编辑 + 离线试扫，审计只读尾部、按动作与阶段筛选。
- **图片白名单用户跳过远程审核**（高信任成员），并支持把命中 `review` 的条目入队人工复核。

> 没有 `safety.toml` 时行为与 1.1.7 完全一致（继续读 `app.toml` 里旧的 `[safety]` 段）；
> 删掉 `safety.toml` 即可一键回到 1.1.7 行为，热加载生效、不需要重启。

## 二、DSH 深度路由：从"必然 404"到真正可用的第二后端

**旧状态（1.1.7）**：内核的 DeepSeek 适配器只说 **Anthropic Messages** 协议
（`<base_url>/v1/messages`），而旧逻辑会把任意非官方 provider 的 `base_url` 注入
`DEEPSEEK_BASE_URL`。真实实例上唯一能用的 provider 是 OpenAI 兼容网关，于是每条"复杂消息"
都先付一次 1.7~1.8 秒冷启动、再拿一个必然的 `404`，然后回退原生。并发被一把进程级锁压成
1，没有忙时回退 / 卡死看门狗 / 预热 / 空闲回收，`/metrics` 也看不到 DSH 状态。

**新状态（1.1.8）**：

- **P0 凭据协议闸门（修 404）**：新增 `credential_protocol`（默认 `auto`）——只认官方
  `api.deepseek.com`、`base_url` 含 `anthropic` 的端点，或用户自己写在进程环境里的
  `DEEPSEEK_BASE_URL`；OpenAI 兼容网关判**不可用**，不注入、不拉起内核、审计一次后静默回
  原生（不再白付冷启动）。网关确实支持 Anthropic 协议时可显式设
  `credential_protocol="anthropic"`；`openai` / `off` 表示明确不路由。
- **P0 网关头代理（新增）**：有些 Anthropic 兼容网关要求每个请求额外带请求头（例如
  OpenCode Go 的 `x-opencode-session`，缺了直接 `400 MissingSessionID`），而内核没有自定义
  请求头入口。现在只要 provider 在 `[providers.<name>.extra_headers]` 里声明了请求头，
  ATRI-X 就在 `127.0.0.1` 上起一个最小反向代理，把 `DEEPSEEK_BASE_URL` 指过去并补齐这些头
  （支持流式 SSE 与 Files API 路径）；没有 `extra_headers` 的 provider（官方 DeepSeek 等）
  **仍然直连**，行为与以前完全一致。代理只监听回环、不落访问日志、状态与审计只报头名字；
  起不来时本轮按失败回退原生，不会把错误端点喂给内核。
- **P1 有界并发 + 忙时回退**：`max_concurrent_prompts`（默认 2，1 = 旧的串行）个 prompt 槽；
  槽满最多等 `busy_wait_seconds`（默认 2 秒），等不到就释放预算预占、**不记熔断失败**、
  静默回原生（审计 `dsh_route_busy`）。同一会话仍只允许一轮（内核与客户端双重保护）。DSH
  轮次同时占用 `[ops].provider_max_concurrent` 闸门，并发化不会把上游打成 429。
- **P1 卡死看门狗**：单轮超过 `stall_timeout_seconds`（默认 90 秒）没有任何 `session/update`
  就发 `session/cancel`，不再让一次 hang 占满槽位等整轮超时；按轮取消不再误伤并发轮次。
- **P1 指标**：`/metrics` 新增 `dsh` 段（并发占用、`admitted` / `busy_rejected` / `completed`
  / `failed` / `stalled` / `cold_starts` / `idle_closes` / `prewarmed`、亲和条目与命中、
  凭据协议、熔断）；桌面端「性能」页「并发实况」按段渲染可读行。
- **P2 预热与空闲回收**：应用启动钩子按 `prewarm`（默认 true）后台预热内核，首轮省 1.7~1.8
  秒；`idle_timeout_seconds`（默认 900 秒）没有在途轮次就关掉内核进程，省约 170 MB 常驻内存
  （下次路由重新冷启动）。
- **P2 会话亲和**：同一聊天**连续**两轮都路由时复用上一轮 DSH 会话、只发「当前用户消息」
  （省掉重复交接的 1~3k 输入 token）；用"历史长度 + 锚点消息摘要"校验连续性，中间夹了原生
  轮次 / 工具轮次 / 历史裁剪 / 会话过期就退回完整交接。失败、看门狗取消、空闲回收都会关闭
  并清缓存；LRU 默认 4 个；内核重启时先尝试 `session/resume`。

> **模型值的写法**：内核的 ACP `model` 选项是 JSON 编码的 **`[provider, model]` 对字符串**，
> 例如 `model = '["deepseek-official","deepseek-v4-pro"]'`（内置可用
> `deepseek-v4-pro` / `deepseek-v4-flash`）。写裸模型 id 会被内核以
> `-32602 unknown model option` 拒绝并降级到内核默认。完整配置示例见
> [`docs/windows-app.md`](../windows-app.md) §8.1 与 `devdocs/dsh-acp.md` §6。

### 已知限制（与 1.1.7 相同，未在本版解决）

- DSH 的工具调用结果回灌仍走 MCP 之外的路径，复杂工具链的"内核内自循环"尚未接全；
- profile 加固（沙箱内工具权限）与熔断状态持久化未做；
- 真实用量（token/cost）仍以原生链路审计为准，DSH 段指标不含逐轮计费。

## 三、安装版：数据与配置目录可选 + 旧数据自动迁移

安装向导在「选择程序目录」之后多一页 **数据与配置目录**：

- 默认 `<安装目录>\data`：配置（`app.toml` / `services.toml` / `state.toml` / `.env`）、会话
  数据库、成员档案、DSH 的 `DSH_HOME`、技能、研究 / draw.io 数据、GUI 状态与日志全部落在
  安装目录里 —— 整个 ATRI-X 文件夹自包含，备份、迁移、拷走都只需处理一个目录；
- 想继续用旧位置就在这一页点「浏览」选 `%APPDATA%\ATRI-X`；
- 升级时预填上一次安装的选择（注册表 `HKCU\Software\ATRI-X\DataDir`，路径含中文也安全）；
- 旧数据自动迁移：`%APPDATA%\ATRI-X` 有数据、新目录为空且两者不同时，安装后询问一次；
  选「是」→ 先完整复制并**逐文件核对存在性 / 大小**，成功后才删除旧目录（失败保留旧目录并
  回退成使用旧位置）。静默安装自动迁移；
- 运行期解析顺序（`atri_x.config.home`，全程序唯一出处）：`ATRIX_HOME` 环境变量 → 安装标记
  `install.json` 的 `dataDir` → `%APPDATA%\ATRI-X`。配置层、GUI 状态、日志、研究 / draw.io、
  技能目录与 sidecar 核验目录全部跟它走；
- 卸载：数据目录在**安装目录内**随安装目录一起删；在**外面**则交互式询问一次，静默卸载保留。

命令行也可用（`atri-x.exe` 自带）：

```bat
:: 脚本安装时指定数据目录
atri-x.exe -m atri_x.dist.install install --data-dir "D:\ATRI-X\data"

:: 手工迁移 / 回退（先复制核对、成功才删旧目录）
atri-x.exe -m atri_x.dist.install migrate --from "%APPDATA%\ATRI-X" --to "<安装目录>\data" --move

:: 看安装状态与运行期实际数据根
atri-x.exe -m atri_x.dist.install status --json
```

便携版行为不变：便携模式数据仍在解压目录 `data\`；标准模式仍用 `%APPDATA%\ATRI-X`。

## 六、已知限制

- 内置 QQ 协议端基于 NTQQ 的非官方 hook，**有账号风控 / 封禁风险**，请用小号并自担风险。
- 本产物无代码签名，SmartScreen 首次运行可能提示；请用 `SHA256SUMS.txt` 核对文件。
- 内容安全是辅助能力，**不构成合规保证**；远程审核会把你判定要审的文本 / 图片发给所选云
  厂商，请自行评估数据合规与费用。
- 安装版若把数据目录放进安装目录，卸载时会随安装目录一起删除（这是自包含安装的语义）；
  想保留数据请把数据目录放在安装目录外，或在卸载提示里选「否」。
